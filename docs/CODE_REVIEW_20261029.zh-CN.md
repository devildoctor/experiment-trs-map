## 1. 已复现的实现问题

### R1：备选分解的 token 级歧义标记不一致（P2）

- **位置**：`scripts/vntrcore.py` 的 `decompose` 内部 `convert`，注释后第 678 行附近；原版第 654 行附近。`scripts/vntrstructure.py` 的 `segment` 也有同类问题，注释后第 172 行，原版第 165 行。
- **触发**：`decompose('ACGT', ['ACAT','ACCT'], return_details=True)` 有两个同分方案；结构支线的 `segment(('ACGT', seed_dictionary(['ACAT','ACCT']), 'HiFi'), return_details=True)` 也可复现。
- **实际结果**：全局 `annotation_ambiguity=True`、`score_gap=0.0`，主方案 token 为歧义；备选 token 的 `annotation_ambiguity=False`。
- **原因**：转换主、备选方案时都与 `alternate_set` 比较，备选方案实际与自身比较。
- **影响**：使用 `annotation_alternatives.json` 等输出的消费者可能误读备选 token。全局歧义没有丢失，不能称为整个程序已经判定确定基因型。D1S80 专用分析另行按主/备选互比重算单元标记，不能将影响外推到所有结果。
- **建议修复**：转换函数显式接收另一方案的签名集合，并补充主、备选对称标记的回归测试。
- **证据**：`root_review_checks.json`、服务器 `review-probes.json` 及核心模块解读中的最小例子。

### R2：位点 ID 校验接受特殊路径分量（P2，配置健壮性）

- **位置**：`scripts/vntrgraph.py` 的 `read_catalog`，注释后第 99 行附近；原版第 97 行。
- **触发**：BED 第四列填写 `ID=..` 或 `ID=.`；当前允许字符的正则没有排除这两个特殊名称。
- **实际结果**：解析器接受 `..`，随后 `args.out/locus.name` 的规范路径可以指向预期输出目录的父目录。
- **影响边界**：非空输出目录检查能拦住部分情况；路径存在性在 Windows 与 Linux 上也可能不同。它是本地配置校验缺口，并非已经证实的远程服务漏洞。本轮没有运行会写入越界分析产物的 `process_locus`，没有证据显示历史运行发生过覆盖。
- **建议修复**：显式拒绝 `.`、`..`，并在创建/写入前验证最终规范路径仍位于预期输出根目录内。
- **证据**：本地解析与路径检查、服务器 Linux 同条件路径探查；均不调用实际分析输出函数。

### R3：候选样本没有 OBS 时，联合证据导出报错（P2）

- **位置**：`scripts/vntrdbg_analysis.py` 的 `main`，注释后第 553 行；原版第 529 行。
- **触发**：全局存在 CAND 和 OBS，但 CAND 属于样本 S，OBS 只属于样本 T。
- **实际结果**：前置检查允许进入；`joint_support` 返回零 tested molecules 与空 evidence。写 `joint_molecules.tsv` 时访问 `evidence[0]`，抛出 `IndexError`，并留下部分结果文件。
- **影响边界**：是合法性检查/空表导出的边界缺陷，不表示当前冻结 D1S80 数据发生了该错误。
- **建议修复**：使用显式表头处理空表；或在写任何结果前明确拒绝不支持的样本组合。如果允许零证据样本，应正常导出零支持摘要和空分子表。
- **证据**：`reproduce_dbg_review.py` 与 `repro_dbg_no_sample_observation.json`，使用三个合成路径及自洽哈希复现。

## 2. 已确认的口径与文档差异

### R4：分子去重键并非全模块一致

主点图、当前锚定和 dBG 来源采用 `[sample, namespace, read_name]`；旧 read-view 在每个 BAM 内按 QNAME 建展示行，structure/summary 支线仍用 `[sample, QNAME]` 计分子支持。独立文库若复用 QNAME，旧支线可能合并主流程可区分的分子；显示行数也不能替代独立支持数。当前常规输入未必触发这个问题，但 README 的全局表述不能覆盖所有支线。后续统一时需同时验证旧结果兼容性，本次仅在注释与解读中明确差别。

### R5：可调支持阈值与颜色、联合查询、历史报告文字不联动

`vntrdbg --min-support` 可调，而图中的颜色分界仍固定为 3；联合分支分析使用自己的默认门槛 3；历史 `vntrdbg_report.py` 的说明文字也写死为同样本 3 个分子。颜色比较的是跨样本的总 `molecule_support`，过滤则按各样本内计数，所以颜色也不能直接表示是否通过过滤。默认 3 的历史运行没有由此被证实错误，但用于门槛 1 或 2 的新结果时可能产生误导。建议各产物读取并明确显示自身实际参数，不把不同阶段的门槛视为一个值。

### R6：旧结构说明中的参数已经漂移

`STRUCTURE_VIEW.md` 仍包含旧版本“最多 12 个候选模板”等描述，当前 `vntrstructure.py` 默认最多 256 个模板、最多 3 轮发现。`README.md` 和历史 METHODS 适合了解演变，精确参数应以对应模块当前 `main` 为准。本次新解读按源码核对，不批量改写历史记录。

## 3. 资源和科学解释限制

- 主锚定和 dBG 准备有将整份位点 BAM 的 SAM 文本读入内存的路径；read-view 逐行流式读取 SAM，但读段、片段和原始记录元数据仍累积在内存中。当前设计针对按位点整理的小输入；本轮没有测量真实全基因组 BAM 的资源消耗。
- 精确 STR 分解在长纯重复中会枚举大量候选终点。本地 Python 3.12 的小规模探查中，300/600/1200/2400 bp 纯 CAG 的时间约为 0.009/0.043/0.187/0.945 秒。输出表达正确；这些数值只是本机探索记录，不是服务器基准或严格复杂度证明。
- 主图候选启发式阈值、侧翼 identity、结构分解编辑上限、图边支持阈值、条件 support_fraction 是不同指标，均不能直接解释为准确率。
- 当前没有“保结构的有损代表单元替换”功能。近似模板注释仍保存实际切片；抽象结构图与精确图是不同产物。
- 不存在单凭节点支持、局部片段、单元数量或候选类名就确认完整等位序列/CN 的依据。终端模板模式明确保留所有 `primitive_cn=NA`。
